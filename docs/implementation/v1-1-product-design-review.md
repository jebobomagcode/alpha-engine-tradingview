## Product and release recommendation

Freeze the product boundary and the causal contract. Keep the detector policies versioned and provisional. The first release should be a private indicator for a **single verified Binance USDⓈ-M perpetual per chart**. Use a standard 5m OHLC host and show 4H regime, 1H structure, 15m area of interest (AOI) and 5m closed reaction. Start with **one continuation profile for each direction** and one primary, pre-known 15m support or resistance zone per side. The dashboard explains the leading candidate, its first unmet condition, any blocker and its exact cutoff. A qualified setup can have unavailable geometry. Historical events and present eligibility are separate. The analysis uses same-contract trade OHLC throughout.

USDT and USDC are initial families. | Grow a versioned list of verified contract/feed pairs. The first successor should earn four engineering claims independently: correct scope, causal decisions on pinned inputs, native behavior on named contracts and saved-script persistence. Trading performance is a separate empirical claim.

## Feasibility and architecture

| Area | Feasibility and concrete constraint | Recommendation |
| --- | --- | --- |
| Product gate | Pine exposes ticker metadata and chart price increments. The documented API does not establish a Binance contract's settlement, current listing status or Binance-specific contract subtype by itself. | Maintain a small external evidence registry embedded as a versioned Pine manifest for each build. Use exact native and standard ticker identifiers, explicit price-feed identity and a metadata compatibility check. Withhold unmatched charts. |
| Contract classification | Binance documents linear USDT/USDC quoted and settled perpetuals. The v0.1.6 frozen XAUUSDT row records `TRADIFI_PERPETUAL`, quote/margin USDT, tick 0.01, and the native chart returned an empty base field. The product-family rule and raw enum need separate fields. | Preserve raw enum and normalized family, require product terms for settlement, accept a specific verified subtype mapping, and scope a missing-base allowance to the exact feed. The older receipt is a useful fixture, not current universal qualification. |
| Price precision and eligibility | Binance warns against using price precision as tick size or quantity precision as step size. TradingView's minimum tick is dataset metadata. A matching tick alone cannot prove product identity. | Use the Binance `PRICE_FILTER` grid and compare native increments. Keep quote asset, margin asset, contractual settlement and optional account collateral mode distinct. No quantity or order-filter promise is needed for nominal geometry. |
| Higher timeframes | Pine supports confirmed HTF values using previous-bar offsets with `lookahead_on`. The current source uses that pattern for 1H/4H EMA context. | Compute each layer in its own source timeframe and return a small packet with timestamps, state, valid-window and identities. Never compute a 15m EMA on repeated 15m closes in 5m context. Dedupe updates by source close, and detect held stale values by expected timestamp. |
| Alternate hosts | `request.security` on a lower timeframe selects one intrabar. `request.security_lower_tf` provides arrays of available bars, with limits and possible realtime/historical revisions. | Defer 15m/1H hosts. Qualify each later against complete ordered 5m event traces, including two state changes in one host bar and missing intrabars. |
| Runtime budgets and chart style | TradingView documents unique request, tuple, intrabar and drawing limits. `chart.is_standard` covers multiple standard OHLC styles including line, bar and candle. | Bundle compact packets, bound plots and objects, profile on the user's plan, and write the requirement as standard OHLC on 5m with candles as the tested default. Gate synthetic chart types. |
| Historical fidelity | Official data can be revised, and TradingView chart and requested feeds can arrive out of sync. Chart state has no Binance receipt timestamp. | Promise no future-input dependence on identical evidence. Log source candle equality before algorithm comparisons. Report differing inputs, insufficient observations or logic mismatches separately. |

**Manifest contract.** Each record should include Binance symbol, raw type, normalized family, listing/status snapshot, quote, margin asset, settlement evidence, exact TradingView trade feed, tick, metadata source and digest, verification date and native capability coverage. Separate **in-scope**, **mapped**, **native-tested** and **ready at this cutoff**. Use effective date/history and recheck newly listed, delisted or changed instruments. Missing current metadata needs a stale/unverified status rather than a live claim. Historical replay must use versioned metadata, with unknown historical eligibility left explicit. Binance's documented kline routes may accept multiple product families following migration. An endpoint's successful response cannot by itself qualify the product. For XAU, record commodity index-mode changes separately from trade-session continuity. A different index regime does not by itself mean the trade chart is closed. Optional public data comparisons can use native HTF klines plus independently aggregated complete 5m windows. Keep both receipts when they disagree.

## Causal contract and setup semantics

Use an explicit opening snapshot and closing transition. Each 5m bar is a half-open interval `[open, close)`. Preserve source raw timestamps and canonical boundaries separately. Binance's inclusive end-of-bar millisecond can normalize to the next interval boundary when the documented convention and exact duration match. It does not establish when an update arrived. Record origin, confirmation close, modeled availability, first eligibility, decision close, replacement/retirement and display time as distinct fields. Pine makes a chart-clock inference. Genuine receipt order requires separately captured evidence.

**Rollover example.** At the 10:15 UTC close of `[10:10,10:15)`, use the prior 15m context ending at 10:00. The newly closed 10:15 source packet first belongs to the 5m bar opening 10:15 and can affect its 10:20 close, if present and qualified. Apply the same rule at 1H/4H and a simultaneous rollover. Mark delayed or missing packets as insufficient for dependent decisions. Do not substitute an older packet at the expected new close or attach a newly born zone to the earlier bar. If a packet is first seen after open, a separate observed-sequence test must disclose that the opening order is unverified. A live/reload difference from a provider race must remain visible in the evidence. Compare a faster boundary-close protocol separately only if it never treats a zone discovered at the shared close as a zone that existed throughout the closing 5m bar. This proposed rule matches the integrated v1 1H rollover observation. The older manual panel showed a newer HTF preview at the same instant, which illustrates why preview and decision snapshots must be labeled separately. [Prior native boundary evidence](phase3-6-v016-market-qualification.md).

**Use separate state fields.** Maintain per-layer data readiness, per-side episode state, qualification/blocker and geometry status, with an immutable event history. A single dashboard headline can summarize these fields. Examples: `LONG WATCH · waiting for 15m support overlap`, `SHORT REACTION · higher-timeframe conflict`, `LONG SETUP · no structural target` and `DATA INSUFFICIENT · 1H warmup`. Full setup qualification needs the required directional, location and reaction gates. Geometry is an independent output, so an absent target should not erase an observed or otherwise valid setup. Record time explicitly in all four rows even if one layer is missing.

**Identity and precedence.** Bind an episode to the product, rule profile/version, side, exact zone/reference IDs and first eligible cutoff. Keep one primary zone per side for the first release, select it using an explicit causal rank and deterministic tie-break, and pin it through the episode. New candidates remain visible in the detailed evidence. Rank only candidates whose own source and lifecycle are eligible. Start with the most recent eligible structural reference of the relevant role, define a stable ID tie-break, and compare nearest pre-known zone on the same frozen windows. Avoid recomputing a selected zone from price movement on every close. Retirement or material anchor/context replacement creates a new decision identity and clears active guides. Preserve observation history. Invalidation, expiry and consumed-reference effects veto active qualification at the same cutoff. Document which boundary is inclusive. After a gap require fresh eligible evidence. A zone-spanning gap or same-bar wrong-side close cannot establish an executable sequence. Keep raw observation diagnostics where defensible. An overlapping pair of opposing AOIs may produce competing watch states, while the continuation profile withholds qualification in an actual 4H/1H conflict. Do not pick the last signal written.

**Geometry.** Use one declared entry reference convention, such as the closed confirming price, plus a structurally selected stop beyond the applicable invalidation boundary and a prior-known target on the correct side. Perform grid normalization, then validate signed distances and compute R from the displayed levels. With side `s = +1` LONG or `−1` SHORT, risk is `s(E − SL)`, reward is `s(TP − E)`, and both must be strictly positive. Log rounding policy and withhold zero-distance or wrong-side cases. Choose structural target first and preserve fixed R multiples as a separate comparator where the source allows them. A close price is a reference and an OHLC span supplies no fill sequence. A target already consumed or invalidated by the qualifying close cannot remain an active guide even if the price ordering still passes. Test this separately from a historical record with frozen geometry. Position size, fee tier, spread, slippage, funding, mark-based liquidation and maintenance margin remain outside the calculation. A trade-price stop reference does not specify a mark-price trigger or assure execution. [M06 risk contract](../methodology/09-m06-risk-and-execution-uncertainty.md).

| Illustrative path | Expected result under the proposed continuation profile |
| --- | --- |
| LONG | Ready 4H/1H up. A pre-known 15m support band 100–101 is overlapped. A valid bullish 5m engulfing closes at 102 with no invalidation. Record reaction and evaluate setup. If a valid prior structural target is 108 and stop reference 99, show nominal 2R. |
| SHORT | Ready 4H/1H down. A pre-known 15m resistance band 99–100 is overlapped. A valid bearish 5m engulfing closes at 98. With prior structural target 92 and stop reference 101, show nominal 2R. |
| Conflict | 4H up and 1H down with a valid 15m supply AOI and bearish 5m reaction. Preserve the short observation and expose the conflict. The continuation profile withholds qualification. |
| Missing | 15m source packet held through a missing interval or a 4H window still warming up. Name the missing layer and its last accepted close, preserve independently valid evidence and withhold dependent output. |
| Invalidation or replacement | A bar overlaps support and closes through its floor, or a newer confirmed anchor supersedes the frozen zone. Show invalidation or reassessment and clear current geometry. Retain the earlier event with its original cutoff. |

The examples are synthetic nominal prices and conditional on a valid price grid. An opposite reaction alone is not an opposing setup. Using no mandatory 5m BOS as the starting comparison avoids requiring the pullback to finish twice. Test an added armed-reference break as a comparator with measured delays and misses. Measure the incremental effect of a 1H alignment veto versus using 1H solely as context. Neither setting has established predictive superiority.

## Dashboard and overlays

The default panel should answer three questions at a glance: which product/feed is running, what became known at the last closed 5m cutoff, and what evidence is still missing. Show one row per timeframe, a one-line decision headline and optional E/SL/TP/R. The expanded panel or tooltip can show zone lineage, ruleset version, invalidation, gap status, current versus archived event and metadata snapshot date. Use text alongside color, and keep the 5m drawing anchor at the actual observation cutoff. Offer optional origin guides with explicit retrospective labeling. Keep one current region per displayed family by default, tier the layers visually, and bound event history. Test dense candles, narrow panels, native floating toolbar overlap, long symbol labels, gaps and complete clearing on an unsupported chart. Standard chart use is self-contained. GitHub and Python remain validation tools.

An alert, ChatGPT summary and cross-market scanner serve different purposes. Defer all three. A future companion should consume versioned evidence and explain it without becoming an alternative decision engine. TradingView alerts use a saved snapshot of the script, settings and chart context, so alert identity and recreation would need their own tests. [TradingView alerts](https://www.tradingview.com/pine-script-docs/concepts/alerts/).

## Development and acceptance sequence

1. **Specification freeze.** Adopt explicit market, time, state and display contracts. Amend the literal perpetual-type requirement, rollover example, EMA/RSI provenance and distinction between setup and geometry. Resolve remaining choices below before authorizing development.
2. **Identity and clock vertical slice.** On one qualified USDT chart, show exact identity and four confirmed source closes, with warmup and gap status. Build a reviewed USDC positive and adversarial exclusion fixtures before claiming breadth. Use the frozen Spot evidence solely for v1 regression. Add qualified same-product perpetual windows with enough pre-roll for chosen filters.
3. **One bidirectional continuation slice.** Add confirmed 1H structure, one 15m S/R family and closed 5m reactions for both sides. Freeze a compact, versioned event schema before widening the existing Python comparator. Compare model-derived direction and episode identity, event class, known-at, price ticks, invalidation and display. Reuse current oracle fixtures and independently specify expected cases. Keep broad tolerance or percentage parity away from event decisions. If EMA float tolerances are needed, specify them separately and verify that they never hide direction flips.
4. **Geometry and interface.** Add tick-safe conditional geometry, then Fib, OB/FVG and momentum context using the same evidence contract. Validate visible/withheld states and drawing retirement on chart, including constrained viewports. Run ablations after the baseline has traces for both sides.
5. **Private release qualification.** Keep existing 148 + 21 regression checks and pinned ancestors. Require exact-source native compile, USDT/USDC identity and four-clock checks, unsupported-chart withholding, visible LONG/SHORT positive and negative paths in exact native calculations, readable layout, source/input readback and a matched-cutoff saved-layout reload. Seek a positive saved-state reload within a bounded session. If absent, record INSUFFICIENT separately from tested historical/live transitions, and explicitly describe the resulting release coverage. Missing positive native logic on either required side or quote family, wrong-feed admission, future leaks, phantom geometry, mismatched source and persistence failures are release blockers. Continuous intrabar, cross-device, actual receipt order, scanning, alerts and profitability remain separate.

The [existing integrated replay](../../research/phase3_6/integrated_replay.py) receives one bullish-context flag for the replay. Its result has structural, zone and reaction fields, without a timestamped four-layer join, Fib or nominal geometry. The [accepted Pine](../../pine/alpha-engine-research.pine) includes those drawings for v1 and a different scope. The Work reconciliation also omits 15m from some later parity fields despite adding it in its summary. Amend the parity matrix to require timestamps, status and provenance for all four layers. Compare **input parity**, **independent model logic**, **native calculation**, **visuals** and **named persistence** separately. A mismatch at one layer cannot be certified by a pass in another.

## Owner choices before freezing

1. **Initial breadth and viewing.** Is it acceptable for v1.1 to launch on a small verified USDT/USDC set with standard 5m as the initial host? Recommended yes. Decide if any specific contract, such as XAUUSDT, or a second host is essential on day one. Other verified TradFi contracts may qualify under the same product rule if the owner intends the contract family to govern regardless of underlying.
2. **First strategy profile.** Is bidirectional continuation sufficient for the first private release, with mixed context and range/breakout/reversal shown as observations until independently qualified? Recommended yes. An affirmative choice leaves those Coach examples in research without pretending to implement them as continuation.
3. **Qualification wording.** Should a valid setup remain visible when a target or stop is unavailable? Recommended yes, with **geometry unavailable** explicit. Requiring complete geometry for the headline changes which setups the user will see and should be a deliberate product decision.

The design is technically feasible within the recommended bounded scope. Keep PR #4 draft and the accepted v8/v7 scripts in place while reviewing these amendments.
